# Лабораторна робота 6 — Слайдер на React

Слайдер на React з іконками (react-icons), кнопками «попередній / наступний» та автоматичною прокруткою кожні 2 секунди.

## Запуск

```
npm install
npm run start
```

## Відповіді на питання

### Чому необхідно використовувати функцію `clearInterval`?

`setInterval` запускає таймер у браузері, який працює незалежно від React і продовжує виконуватися, доки його явно не зупинити. Якщо не очищати інтервал, то:

- при кожній зміні `index` (а отже, при кожному повторному запуску ефекту) створюватиметься **новий** таймер, а старий продовжуватиме працювати — таймерів ставатиме все більше, слайди перемикатимуться хаотично та дедалі частіше;
- після видалення компонента з DOM (unmount) таймер і далі викликав би `setIndex` для неіснуючого компонента — це **витік пам'яті** та попередження React.

Тому в `useEffect` повертаємо функцію очищення `return () => clearInterval(slider)`. React викликає її перед кожним наступним запуском ефекту та при розмонтуванні компонента, і так завжди залишається активним лише один таймер.

### Чому другим параметром хука `useEffect` передаємо `[index]`?

Другий параметр — це масив залежностей: він визначає, коли ефект потрібно запускати повторно.

- Колбек `setInterval` «замикає» (closure) значення `index`, яке було на момент створення таймера. Якщо залежностей не вказати (або передати `[]`), ефект виконався б лише один раз, і таймер завжди працював би із початковим значенням `index` — слайдер перемкнувся б лише один раз.
- З `[index]` ефект перезапускається щоразу, коли змінюється поточний слайд (у тому числі після кліку на кнопки вручну): старий інтервал очищається, а новий створюється з актуальним значенням `index`, і відлік 2 секунд починається заново.
- Без другого параметра взагалі ефект запускався б після кожного рендеру, що зайве.

> У коді також додано `people.length` до масиву залежностей, щоб ESLint (`react-hooks/exhaustive-deps`) не видавав попереджень; на поведінку це не впливає, оскільки довжина масиву не змінюється.
